# Explain it on a whiteboard

Ask "explain how a TCP handshake works" or "sketch how React renders" and Kite opens a whiteboard. It draws the idea one piece at a time in a hand-drawn style while it narrates, and the kite holds the marker. Turn it off in **Settings → Actions**.

Implementation checked on **8 October 2026**: **Phase 1 is complete; Phase 2's 10 items and Phase 3's eight items are implemented behind development flags**. Phase 2's Groq first-stroke gate and Phase 3's scored provider-clarity gate remain pending. Phase 3's live timing fixture passes its cue/gap targets. Phase 0's original three-provider baseline gate remains separate. See [the phase roadmap](whiteboard-roadmap.md#implementation-status--8-october-2026) for evidence and conditions.

## Using it

- **Start:** ask Kite to explain, compare, or walk through something with a tool-capable model. No approval is needed: the board is Kite's own drawing and nothing on your PC changes.
- **Follow:** each beat is spoken (or captioned when voice is off) while its shapes, arrows, and words are drawn. Parts Kite talks about again get circled. **Settings → Actions → Whiteboard captions** can keep captions visible during speech; they also show when no voice is selected or accessibility support is active.
- **Voice commands** (hold the shortcut and say):
  - "wait", "pause" → pause. The current beat stays on the board.
  - "continue", "go ahead" → carry on (the paused beat is said again).
  - "next", "skip" → the next beat.
  - "repeat", "say that again" → the current beat again.
  - "replay", "start over" → the whole lesson from the beginning.
  - "close the board", "stop" → put the board away.
- **Ask about it:** anything else you say goes to the model, which sees every element on the board by id. It answers by adding to the same board (new beats play, then Kite waits before the rest of the original lesson) or by starting a new one.
- **Point at it:** hold the shortcut and circle or tap part of the board while asking "what's this?". Kite tells the model which elements you marked. No screenshot is taken for marks on the board.
- **Board buttons:** Pause/Resume, Next, Replay, Bigger/Smaller, Copy (PNG to the clipboard), Save (PNG to Documents › Kite Boards), and Close. Say "make it bigger" or "presentation mode" for the larger panel, and "make it smaller" to return. Drag the title bar to move it, the corner to resize it, the wheel to zoom, and the paper to pan; Fit resumes automatic framing.
- **Dev panel:** **Demo whiteboard** plays a built-in lesson ("How a kite flies") without a model.
- **Find it again:** completed or closed lessons save locally in **History → Whiteboards**. Search titles or diagram labels in the History search field and click a board to replay it. Thumbnails include the visible scene; reopening plays the saved script, including streamed and follow-up beats. Deleting its conversation deletes its saved boards. The built-in demo is not archived.

## How it works

The released model contract plans the whole lesson in one `explain_on_whiteboard` call: a title and up to 16 beats, each with a spoken line and the elements it adds on a 1600 × 900 canvas (rectangles, ellipses, diamonds, text, arrows between elements, and lines, in eight colors with optional hatching). Kite's code sizes shapes to their labels, binds arrows edge to edge, keeps a request and its reply apart, and puts arrow labels beside the line. Drawing starts when a beat's audio starts; the next beat waits for both. [ADR 013](adr/013-whiteboard.md).

The lesson starts before the model has finished writing it. Its input streams in, and each beat is handed to the board once it is complete. Beat 1 is drawn and narrated while the model writes the rest; reaching the newest beat waits for the next. The final call adds whatever has not arrived. A lesson cut off mid-stream plays the beats that did arrive. The lesson is the whole answer: the voice turn ends on it, with no filler line. Whatever the model said before the call ends as soon as the lesson starts streaming, and narration follows it.

Lessons are repaired rather than rejected (`sanitizeLesson` in `src/shared/board.ts`):
- Elements that can't be drawn are dropped.
- Duplicate ids are renamed.
- References to ids that aren't on the board are dropped.
- Numbers are clamped.
- A shape written with `text` gets it as its label.

The model is told what was fixed.

Text uses bundled Excalifont (OFL-1.1), with shared glyph widths generated by `scripts/font-metrics.cjs` using Chromium. The default panel is 1400 × 900 on a 1080p display, capped at 90% on smaller displays. `planCamera()` frames the current beat and connected elements at a scale targeting at least 14 px text, with a 500 ms glide before drawing; reduced motion cuts to the new view. The finished-board overview can use smaller text. Coordinates still come from the model, but `repairBeats()` in `src/shared/boardLayout.ts` sizes labels, separates collisions, detours obstructed arrows while keeping their bindings, and halos text on lines. Each new beat finds space around the existing repaired picture. Rendering, model context, archives and replay use those same repaired coordinates.

### Phase 2 development path

Start Kite with `KITE_BOARD_PHASE2=1` to use the new contract, still gated by **Settings → Actions → Whiteboard**. The ordinary voice turn sends only `{ topic, focus?, level?, mode }`. `src/main/board/planner.ts` makes a separate streaming specialist call with a 4,096-token budget, recent text conversation and current board structure. **Settings → Models → Whiteboard model** chooses the specialist independently; Automatic provisionally uses DeepSeek Flash when its key is saved, otherwise the main model. The picker appears only with phase 2 enabled. Setting the environment flag to `0` uses the released legacy tool.

The specialist writes a coordinate-free `BoardScript`, using compact escaped line records. Nodes and edges finish at a `ready` boundary; the parser then emits completed narration/reveal beats. Local family modules handle sequence, flow, architecture, tree, cycle, layers, compare, timeline and freeform diagrams. Flow, architecture and tree use a lazy ELK worker with label measurements, nested groups and orthogonal routing. Sixty generated Tabler icons draw through the same pen player.

The complete graph is laid out before beat 1, so streaming only reveals its fixed placements. Follow-ups pin the complete original graph, including future beats, and put additions in free space beside it. This append-only policy avoids relayout; arbitrary element editing remains future work. Phase 3 adds explicit teaching move/swap actions. A close/new-board action aborts stale planning. Archives store both structure and compiled beats; old coordinate-only lessons replay their original geometry through the legacy adapter. [ADR 018](adr/018-structured-whiteboard.md) records the contract, format measurements, model selection, licenses and release gate.

### Phase 3 development path

Start Kite with `KITE_BOARD_PHASE3=1`. It enables the structured planner and the teaching extension, using the existing Whiteboard action toggle and model picker. `KITE_BOARD_PHASE2=0` explicitly disables both extensions. Phase 3 uses streamed JSON for nested action metadata; Phase 2 continues using compact line records.

Elements start on explicit cue phrases or matching label words in Cartesia's timestamps. The pen follows the actual Web Audio playback clock; voice-off timing follows reading speed. Phase-3 cameras cut to the current beat so a glide cannot delay its first cue. One known next beat's audio is prefetched silently, then adopted only when that beat starts. Unknown streamed beats and answer-waiting questions cannot eliminate all network waits.

Beats can underline, pulse, dim other parts, number steps, strike out old values, erase elements, move pointers and swap cells. Bound arrows move with their endpoints. Data boards show arrays with fixed indices, stacks, queues, linked lists, pointers and hash buckets. Worked equations align their equals signs and side notes; a lazy MathJax worker turns TeX into paths the pen traces. Plots use bounded arithmetic/functions, sampled curves, points and shaded areas, with no executable expression evaluation.

Ask **"teach me"** or **"quiz me"** for a lesson with answer-waiting question beats. Answer while holding the normal shortcut; Kite sends the question and answer to the model for feedback on the same board, then waits before continuing the original lesson. Say **"simpler"**, **"more detail on X"**, **"give me an example"**, or **"summarize"** for a planned follow-up. These requests rely on the specialist's teaching contract; the harness does not prove every generated explanation is semantically correct.

The added controls are **Previous**, numbered beat buttons and **0.75×–1.5× lesson speed**. Voice commands include **"previous"**, **"slower"**, **"faster"** and **"normal speed"**. **Next/skip** or **continue** can skip an unanswered question. A drill-down can open a child board with a breadcrumb; **Go back/"go back"** restores its paused parent with the original scene and archive identity. Lesson speed does not change ordinary conversation speed. [ADR 019](adr/019-whiteboard-teaching.md) explains the protocol and timing tradeoffs.

## Privacy

Lesson text goes to the configured conversation model and, with phase 2 enabled, the selected specialist. The specialist receives at most six recent text messages and board structure; conversation images and screenshots are excluded from that request. The board is excluded from Kite's own screen captures. Completed or closed lessons, their scene and a small PNG thumbnail are saved locally in Kite's history database. These thumbnails are not sent to a model. Deleting conversation history deletes its boards. The Save and Copy buttons explicitly export a PNG; automatic history saving does not export files to Documents.

## Measuring

`src/shared/boardMetrics.ts` scores a board as numbers: colliding elements, labels that don't fit their shape (or had a word split), arrows and lines through shapes they don't connect, crossing arrows, free text lying on a line, and the smallest text on screen in the default panel on a 1080p display. Lesson readability is measured at each beat's camera; finished-board overview text is recorded separately. The harness and the dev panel both use it.

- **Harness:** `npm run eval:board` runs the 60 golden prompts and follow-ups through the model/tool path, applies the same scene repairs as playback, and records tokens, metrics, streaming readiness and the final call. It has no renderer, so `firstStroke` is null on fresh runs. `npm run eval:board:live` measures actual first stroke with the real overlay, using its renderer acknowledgement after font/camera readiness. `npm run eval:board:phase1` deterministically revalidates the frozen [phase 0 corpus](performance/whiteboard/phase0-baseline.json) and writes [the current repaired corpus](performance/whiteboard/latest.json) and [validation results](performance/whiteboard/phase1-replay.json). Model timings in that replay remain historical; [fresh latency samples](performance/whiteboard/phase1-live.json) are separate. `npm run eval:board:gallery` renders the [122-board gallery](performance/whiteboard/index.html).
- **Dev panel:** one line for the latest lesson, with the time from the model request to the renderer's actual first drawing frame (including the camera glide), output tokens, input/scene fixes, and lint counts. It holds numbers only, never lesson text; the same numbers are logged as `board:lesson`.

For phase 2, `npm run eval:board:phase2` runs 60 fresh specialist prompts on three providers; `--formats lines,json --family sequence,flow --limit 2` runs the paired format comparison. `npm run eval:board:phase2:replay` recompiles the stored scripts and checks every beat. `npm run eval:board:layout` benchmarks the worker plus routing/lint. `npm run eval:board:live -- --phase2 --provider deepseek --model deepseek-flash` measures both voice routing and specialist planning through actual first stroke; the same command accepts Groq and its model id. Run `npm run eval:board:gallery -- --in docs/performance/whiteboard/phase2-golden.json --out docs/performance/whiteboard/phase2` for the [phase-2 gallery](performance/whiteboard/phase2/index.html). The new baseline is [phase2-golden.json](performance/whiteboard/phase2-golden.json); `latest.json` retains the phase-1 baseline until default rollout. Rate limits and failed calls remain visible in reports. `npm run assets:board-icons` regenerates the 60 icon stroke paths.

## Verification

Phase 3 adds nine unit tests (**281 total, all passed serially**) plus native MathJax-worker and renderer teaching checks. The [live audio fixture](performance/whiteboard/phase3-live.json) measures six cues over three fully known beats: **19.5 ms median cue error**, with **406 ms maximum dead air**, using actual Cartesia/Web Audio timing and muted speaker output. The [nine targeted provider probes](performance/whiteboard/phase3-provider-probe.json) are lint-clean and sort the test array correctly with an `ask` pause on all three providers. These results do not replace the pending scored clarity comparison against Phase 2. See the [Phase 3 gallery](performance/whiteboard/phase3/index.html) and [roadmap verification](whiteboard-roadmap.md#phase-3-verification--8-october-2026).

The earlier Phase 1/2 baselines are retained.
